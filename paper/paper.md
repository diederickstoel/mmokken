# Summary

`mmokken` is a Python implementation of Mokken Scale Analysis (MSA), a
non-parametric item response theory framework introduced by @mokken1971 for
ordinal psychometric measurement. It ports the unidimensional analyses,
the Automated Item Selection Procedure (AISP) including its
genetic-algorithm variant, and the standard diagnostic checks
(monotonicity, restscore, P-matrix, reliability, person-fit) from the R
`mokken` package [@vanderark2007] into the modern Python data-analysis
ecosystem. Numerical results are validated bit-for-bit against the current
R `mokken` 3.1.2 release on CRAN and within display-precision against the
original MSPWIN 5 program [@molenaar2000mspwin], the historical reference
implementation produced by ProGAMMA in 2003.

# Statement of Need

Mokken Scale Analysis is a widely used psychometric framework for ordinal
data, with applications across personality assessment, health measurement,
educational testing, and political science [@sijtsma2002introduction;
@sijtsma2017tutorial]. The reference implementation is the R `mokken`
package, which itself was derived from the original MSPWIN 5 program. Until
now, Python users have lacked a comparably featureful implementation:
existing Python IRT libraries target parametric models (Rasch, 2PL, GRM)
rather than Mokken's non-parametric approach.

`mmokken` closes this gap. The package's distinguishing contribution is its
**three-way validation**: numerical equivalence against both the original
MSP 5 (1990s/2003) and the current R `mokken` 3.1.2 (CRAN release of
June 2024). This is unusual; most Python ports of R packages validate
against a single reference. The dual reference matters because algorithmic
choices and default conventions sometimes diverged between MSP 5 and the
later R rewrite, and cross-checking against both surfaces silent
discrepancies that a single-reference test suite would miss.

The value of the three-way comparison is concrete: the first run of the
parity script on the canonical MSP 5 test dataset (828 respondents × 17
odour-annoyance items) uncovered three latent bugs in the package's own SE
branch of `coefH` and the underlying `weights` helper — bugs that the
original 3-item × 3-category unit tests had failed to catch because they
asserted only output shapes, not numerical values. The bugs were fixed
before release; the affirming parity table, including standard-error
columns, is committed to the repository at `docs/parity_results.md` and
regenerated by `scripts/run_three_way_parity.py`.

A second, more personal motivation. The first author was taught Mokken
Scale Analysis directly by Robert J. Mokken, whose recurring opening
question to consulting analysts — *"Mooi al die data, maar wat is je
theorie?"* ("nice data, but what is your theory?") — anchors the
package's design. Mokken's preferred workflow combined a
semantically curated set of theory-anchored start items with
data-driven scale completion via AISP. `mmokken` exposes both: the
`StartSet=` mechanism for the algorithmic step, and (as a Track A
companion package) tooling that operationalises the semantic-cohesion
step using LLM embeddings. The protocol is documented in
`docs/methodology_notes.md` so that the seven-step procedure is not
lost to oral tradition.

`mmokken` is also the foundation for a planned multidimensional
extension (mMokken) and the multi-scale generalisation of the Stoel
scalability metric [@stoel2011scalability], both of which are
forthcoming. The package is positioned as one family within a broader,
scikit-learn-style measurement-model ecosystem (see the architecture
decision record in the repository).

A complementary outcome of the historical comparison: a feature-gap
analysis of MSP 5 against R `mokken` 3.1.2
(`docs/msp_vs_r_gap_analysis.md`) identifies three diagnostic features
that R inherited only partially — the `Restsplit` non-intersection
check, the weighted-vs-unweighted H toggle, and the `Groupvar`
mechanism for measurement-invariance and differential-item-functioning
testing. These are slated for `mmokken` v0.2 because the
career-progression demonstration case (1,700 employees across multiple
organisations) explicitly requires the group-comparison machinery.

# Functionality

The public API at v0.1.0:

- **Scalability coefficients.** `coefH` (Loevinger H with asymptotic
  standard errors), `coefHTiny` (fast path without SE), and `coefZ`
  (Z-statistics under the classic, Wald-based, and range-preserving
  formulations).
- **Automated Item Selection Procedure.** `aisp` orchestrates scale
  construction with either the sequential normal search (`search_normal`)
  or the genetic algorithm (`search_ga`). The GA is implemented in pure
  Python; the rationale (avoiding a pybind11 bridge to R's C++ kernel,
  ensuring transparency for methodology readers, supporting future
  multidimensional variants) is documented in the repository's ADRs.
- **Diagnostic checks.** `check_monotonicity` (manifest), `check_restscore`
  (pairwise non-intersection), `check_pmatrix` (P(++) / P(−−) matrices),
  `check_reliability` (MS, Cronbach's α, Guttman's λ₂, item-rest
  correlations), and `check_errors` (Guttman G+ / Mokken O+ person-fit
  indices with med-couple-adjusted upper fences).
- **Data utilities and I/O.** `recode` (reverse-coding), `twoway`
  (two-way imputation), and `load_msp_dataset` for reading the legacy
  MSP 5 `.dat` + `.var` format. The MSP loader allows researchers with
  historical MSP data to migrate to a Python workflow without
  re-formatting their datasets.

Multilevel branches (`MLcoefH`, `MLcoefZ`, `MLweight`, and the
`level_two_var` paths in the existing functions) raise
`NotImplementedError` in v0.1.0 and are scheduled for a later release.

# Validation

`mmokken` ships with two complementary validation suites:

- **Unit and golden tests.** 87 tests, including six R-golden tests that
  invoke `Rscript` and compare element-wise against R `mokken` outputs on
  the bundled `acl` dataset. All deterministic statistics agree to
  better than 1×10⁻⁹.
- **Three-way parity benchmark.** `scripts/run_three_way_parity.py`
  reproduces the comparison between MSP 5 (frozen reference numbers
  harvested from `TEST full report.txt`), R `mokken` 3.1.2 (invoked at
  runtime via `Rscript`), and Python `mmokken` on the bundled MSP 5
  odour-annoyance test set. The genetic-algorithm AISP is compared
  distributionally across five seeds; the dominant 8-item scale is
  recovered identically by R and Python in every run, with mean
  Rand-style item-pair agreement of 0.875 across the full partitions.

Continuous integration runs the unit test suite on Python 3.10, 3.11, and
3.12 across Ubuntu, macOS, and Windows. A dedicated job installs R 4.4.1
and runs the R-golden tests; the parity benchmark is reproducible from
the script.
